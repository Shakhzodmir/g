# Проверка речи («Nutq tekshiruvi»): спецификация скрининга, плана и отслеживания

**Статус: ЧЕРНОВИК v0.1, не утверждён специалистом.** Функция написана без участия логопеда, невролога и носителей языка. Все вопросы, пороги, советы и формулировки ниже, а также тексты в `src/features/check/` нужно проверить и утвердить до выхода (раздел 9). Без этого функцию не выпускаем (см. также `docs/content-review-v0.1.md`, раздел «Проверка речи»).

Идея взята из разбора конкурента (`docs/competitor-logosmart.md`, разделы 4, 7 и 9: воронка «возраст → что тревожит → быстрый скрининг → подробная оценка → план на 15 минут → отметки → повторы на 7/14/30 день → специалист»). Вопросы, тексты и порядок написаны нами заново. Ничего из материалов конкурента не копировалось.

## 1. Что это и чем не является

- Это **ориентир для взрослого**, не диагноз и не медицинская оценка. На каждом экране с результатом и в отчёте стоит строка «Bu tibbiy tashxis emas / Это не медицинский диагноз».
- Это отдельная часть раздела для взрослых («Ota-onalar va mutaxassislar uchun»), за родительским замком (`ParentGate`). Маршрут: `/parent/check`.
- **Всё остаётся на устройстве.** Ответы хранятся в IndexedDB профиля. Сеть не используется вообще. Ничего не отправляется само: «Поделиться», «Скопировать» и ссылка в Telegram работают только по нажатию.
- **Нет напоминаний вне приложения** (никаких push-уведомлений). Когда пора повторить проверку, в приложении появляется баннер.
- **Нет озвучки.** Новых звуковых клипов нет, `speak()` в этой функции не вызывается. Это текст для взрослого.
- Пользователь **не видит процентов и слова «риск»**. Он видит только три уровня по каждой области, всегда значком и словами, а не только цветом:

| Значок | uz | ru |
|---|---|---|
| галочка в круге, сплошная рамка | Yaxshi | Хорошо |
| глаз, пунктирная рамка | Kuzatamiz | Наблюдаем |
| восклицательный знак в круге, толстая рамка | Eʼtibor kerak | Нужно внимание |

## 2. Три отдельных проверки

Каждая проверка имеет свой вид (`kind`), свои вопросы, область, историю, план и расписание повторов. Данные одного вида не смешиваются с другим.

| `kind` | Для кого | Вопросов | Области |
|---|---|---|---|
| `child` | Речь ребёнка. Возраст 1–2, 2–3, 3–4, 4–5, 5–7 лет (возраст выбирает набор вопросов) | 5 в быстром скрининге; 18 в подробной оценке (6 областей × 3) | словарь и фразы; произношение звуков; понимание речи; плавность; внимание и общение; артикуляция и дыхание |
| `asd` | Признаки, связанные с общением, 1–5 лет (возраста 1–2, 2–3, 3–4, 4–5) | 18 (6 × 3), один набор | совместное внимание; отклик на имя; указательный жест; подражание; игра; реакции на ощущения |
| `adult` | Взрослые после инсульта, при афазии и похожих трудностях | 18 (6 × 3) | понимание речи; поиск слов; чёткость речи; плавность; чтение и письмо; внимание и память |

### Формулировки для проверки `asd` (обязательные правила)

- Спокойный тон. Перед первым вопросом (экран выбора возраста) стоит блок: «это не диагноз и **не определяет аутизм**; оценку проводит специалист с помощью **проверенного (валидированного) инструмента**». Тот же текст стоит на экране результата и в отчёте.
- В вопросах нет слов «аутизм», «РАС», «отклонение», «риск». Речь только о конкретном поведении (взгляд, жест, имя, подражание, игра, реакции на звуки и прикосновения).
- Никаких «баллов в процентах» и нет вывода «у ребёнка есть/нет». Результат = что понаблюдать и что делать дома, а при сомнениях: к кому обратиться.

## 3. Поток экранов

```
Родителям → «Проверка речи» (хаб) → выбор проверки
 child : возраст → что тревожит (мультивыбор) → быстрый скрининг (5)
           ├ всё хорошо (≥80% баллов и ни одного «нет») → «Пока всё хорошо»: закончить или пройти подробную
           └ иначе → «Давайте посмотрим внимательнее» → подробная оценка → результат
         (подробная оценка охватывает области из «что тревожит» + области, где быстрый скрининг не «Хорошо»)
 asd   : вступление и выбор возраста → 18 вопросов → результат
 adult : вступление → 18 вопросов → результат
Результат → «Открыть план на сегодня» → экран проверки: результат, план, серия, расписание повторов, история, отчёт
```

«Что тревожит» (мультивыбор) сужает подробную оценку. «Не знаю» или пустой выбор означает все шесть областей:

| Выбор родителя | Области подробной оценки |
|---|---|
| говорит мало | словарь и фразы |
| неправильно произносит звуки | произношение звуков; артикуляция и дыхание |
| плохо понимает речь | понимание речи |
| заикается / повторяет | плавность |
| мало контакта глаз и отклика на имя | внимание и общение; понимание речи |
| дыхание ртом, слюнотечение, жевание | артикуляция и дыхание |
| не знаю | все шесть |

Повтор через 7/14/30 дней идёт по сокращённому пути: возраст запоминается; вопросы про «что тревожит» не повторяются; если базовая проверка была подробной, задаются те же области подряд, без быстрого скрининга.

Выйти можно в любой момент кнопкой «Chiqish / Выйти» (если уже есть ответы, спрашиваем подтверждение). Незавершённая проверка не сохраняется: хранится только законченный результат.

## 4. Подсчёт и пороги

**Все пороги лежат в одной константе `CHECK_CONFIG` в `src/features/check/config.ts`.** Она помечена как черновик, не прошедший валидацию. Версия порогов (`CHECK_CONFIG.version`) записывается в каждый результат.

```ts
// src/features/check/config.ts (выдержка)
points:  { yes: 2, sometimes: 1, no: 0 }
domain:  { goodMin: 0.8, watchMin: 0.5 }          // доля набранных баллов по области
quick:   { goodMin: 0.8, anyNoMeansLookCloser: true }
overall: { goodMin: 0.8, watchMin: 0.5, capAtWatchIfAnyAttention: true }
plan:    { minutes: 15, maxFocus: 3, whenAllGood: 2 }
retestDays: [7, 14, 30],  retestEarlyGraceDays: 2
keepResults: 30,  keepTickDays: 120
```

- Ответ даёт 2 / 1 / 0 баллов. Во всех вопросах «да» означает хорошо.
- **Область** (3 вопроса, максимум 6 баллов): доля ≥ 0,8 → «Хорошо» (5–6 баллов); ≥ 0,5 → «Наблюдаем» (3–4); иначе «Нужно внимание» (0–2). Если проверка закончена после быстрого скрининга, по области задан один вопрос (кроме возраста 1–2 года: там в области «внимание и общение» два, а «плавность» не спрашивается), доля считается так же: один вопрос с ответом «да» даёт «Хорошо», «иногда» даёт «Наблюдаем», «нет» даёт «Нужно внимание».
- **Быстрый скрининг** (5 вопросов, 10 баллов): «Пока всё хорошо» только при доле ≥ 0,8 **и** без единого ответа «нет». Достаточно одного «нет», чтобы предложить посмотреть внимательнее. Это не результат, а переход к подробной оценке.
- **Общий уровень**: уровень средней доли по областям (те же 0,8 и 0,5), но не лучше «Наблюдаем», пока хотя бы одна область «Нужно внимание».
- Доли хранятся только для упорядочения (какая область слабее). Пользователю они не показываются.
- **Улучшение после повтора** (сравнение с предыдущей проверкой этого вида): «улучшение», если **не осталось областей «Нужно внимание»** или **общий уровень вырос**. Иначе показывается спокойный экран «Подумайте о консультации специалиста» с перечнем, к кому обратиться, и ссылкой на `/parent/help`. Для самой первой проверки или нового старта сравнивать не с чем: показывается обычный результат.
- Вопрос о том, как сравнивать «в динамике» при смене набора вопросов (ребёнок перешёл в следующую возрастную группу между повторами), оставлен специалисту (раздел 9).

## 5. План на 15 минут в день

План собирается из того, что в приложении уже есть, и из советов без экрана.

1. Берутся области, которые не «Хорошо», от самой слабой (по уровню, затем по доле баллов), не больше `plan.maxFocus` = 3. Если всё «Хорошо», берутся `plan.whenAllGood` = 2 самые низкие области, чтобы привычка продолжалась.
2. Для каждой области есть **3 совета для взрослого** (3–5 минут каждый, оригинальный текст) и **3 задания в приложении** (3–5 минут): ссылка на существующую игру, разминку Огизча (зеркало, дыхание, голос), карточки-символы, расписание, таймер, чтение историй. Все маршруты сверяются с реестрами `src/features/games/registry.ts` и `src/app/features.ts` тестом `content.test.ts` (аудитория игры совпадает с видом проверки).
3. На день выбирается набор по кругу между слабыми областями так, чтобы сумма была **не больше 15 минут** и чтобы в плане были и совет, и задание в приложении. Набор зависит от номера дня: в один и тот же день он всегда одинаковый, завтра меняется.
4. Задание в приложении открывается кнопкой «Ilovada ochish / Открыть в приложении» (если профиль, который сейчас активен, вообще может открыть этот экран; детские игры недоступны взрослому профилю и наоборот).

Большая часть плана состоит из советов без экрана. Так задумано.

Соответствие областей заданиям в приложении, а также все советы лежат в приложении Б.

## 6. Отслеживание

- **«Сделано сегодня».** У каждой задачи плана есть кнопка-отметка (значок и текст, не только цвет; состояние читает программа чтения с экрана). Отметка хранится по местной дате (`YYYY-MM-DD`) и id задачи. Отметку можно снять.
- **Серия дней подряд.** День засчитывается, если отмечена хотя бы одна задача. Серия не обрывается, пока сегодняшний день ещё не закончился. Показываются текущая серия, лучшая и число дней занятий. Даты в будущем (часы переведены назад) игнорируются.
- **Повторные проверки на 7, 14 и 30 день** от начала плана. Повтор засчитывается отметке, если он сделан в её день или позже, или не более чем на 2 дня раньше. Один поздний повтор закрывает все отметки, до которых он дотянулся, и сразу не пристаёт повторно. Отметка остаётся «пора» до тех пор, пока её не закрыли (она не истекает).
- **Баннер в приложении** «Пора повторить проверку»: на странице «Родителям», в хабе проверок и на экране проверки. Это единственное напоминание. Push-уведомлений нет.
- **История результатов** по профилю и виду проверки: дата, быстрая или подробная, повторная ли, общий уровень, сколько областей требуют внимания. Хранится до 30 результатов на вид, отметки за последние 120 дней.
- **Цикл завершён**, когда закрыты все три отметки. Новая проверка начинает новый план и новое расписание.
- «Новая проверка» (не повтор) всегда доступна и всегда начинает новый план.

## 7. Отчёт и отправка

- **Отчёт на одну страницу A4** (`/parent/check/<вид>/report`): заголовок, вид проверки, дата, возраст, при желании имя, таблица областей с уровнем (значок + слова), общий уровень, последние до 5 результатов, сколько дней занимались из последних 14, предупреждение «это не диагноз», подпись. Двуязычный: сначала язык интерфейса, под ним второй (специалист может читать на любом из них). Печать использует те же приёмы, что `Print.tsx`: `data-no-print` у всего, кроме листа, `@page { size: A4 }`, лист на экране выглядит как белая бумага при любой теме. Автотест проверяет, что при печати получается ровно 1 страница.
- **Имя в отчёте выключено по умолчанию.** Пока родитель не включит переключатель, имени нет ни на листе, ни в тексте для отправки.
- **Текст для отправки** (тот же, что на листе, без таблицы) виден на экране заранее. Способы, все только по нажатию: Web Share API (если браузер умеет), «Скопировать текст», ссылка Telegram `https://t.me/share/url?url=<адрес приложения>&text=<текст>`. Ссылка открывается в новой вкладке (`noopener`); в ней нет ничего, кроме адреса самого приложения и того же текста.
- Никаких процентов и слова «риск» в тексте.

## 8. Модель данных

**Отдельная таблица Dexie `checks`** (схема версии 2), а не таблица `events`.

Почему не `events`:
- `events` чистится: записи старше 180 дней удаляются (`pruneOldEvents`), а история проверок и расписание 7/14/30 не должны пропадать при очистке журнала;
- `events` — журнал нажатий (одна строка = одно событие) с плоскими метаданными (импорт режет ключи до 12 и значения до 200 знаков). Проверка — структурированный документ (ответы, уровни, план, отметки), который изменяется;
- отдельная таблица легко экспортируется, импортируется и удаляется целиком вместе с профилем.

```ts
interface CheckRow {            // ключ: `${profileId}:${kind}`, индекс: profileId
  id: string; profileId: string; kind: 'child' | 'asd' | 'adult'
  results: CheckResult[]        // старые первыми, не больше 30
  plan: { startedTs: number; baselineResultId: string; focus: DomainId[] } | null
  ticks: Record<string /* YYYY-MM-DD */, string[] /* id задач */>
  updatedAt: number
}
interface CheckResult {         // id, ts, stage 'quick'|'full', age, concerns, retest,
  answers: Record<string, 0|1|2>  // id вопроса → ответ
  fr: Partial<Record<DomainId, number>>      // доля баллов 0..1 (только для упорядочения)
  bands: Partial<Record<DomainId, 'good'|'watch'|'attention'>>
  overall: 'good'|'watch'|'attention'; cfg: number   // версия порогов
}
```

Что сделано вокруг таблицы:
- **Версия Dexie 2**: объявлена только новая таблица, остальные переходят без изменений. Тест открывает базу версии 1 и проверяет, что данные не теряются.
- **Резервная копия `.gapimiz`** (`src/features/parent/backup.ts`): в файл попадает необязательный массив `checks` (строки этого профиля). Номер формата остаётся 2: поле добавочное, файлы без него (старые) по-прежнему импортируются, и в этом случае проверки, уже лежащие на устройстве, не трогаются. Разбор файла заново собирает каждую строку из проверенных полей (`sanitizeRow`): идентификатор профиля и ключ берутся не из файла, чужие или повреждённые строки отбрасываются и попадают в отчёт «что было пропущено» (`ignChecks`), опасные ключи (`__proto__` и т. п.) режутся, числа ограничиваются. При импорте строки профиля заменяются целиком. Не больше 12 строк просматривается, по одной на вид.
- **Удаление профиля** стирает его проверки в той же транзакции (`useProfileStore.remove`) и забывает их в памяти (`clearProfileLocalState`). **«Стереть всё»** очищает таблицу (`wipeDatabase`, `wipeAllData`).
- **Без IndexedDB** (приватный режим) проверка работает в памяти до закрытия страницы, как и остальное приложение; на экранах стоит обычная плашка «данные не сохранятся».
- Данные нескольких профилей на одном устройстве не смешиваются: ключ строки содержит id профиля, экран читает строки только активного профиля, а перед чтением строка проходит через тот же `sanitizeRow`.
- Можно удалить данные одной проверки кнопкой на экране проверки (с подтверждением).

## 9. Что обязательно должен утвердить специалист до выпуска

Нужны: логопед/дефектолог (узбекский и русский), детский невролог или врач, занимающийся развитием детей, носитель узбекского из Ташкента и из региона, носитель русского из Узбекистана. Отметьте в таблице: согласовано / исправить.

### 9.1. Логопед

1. **Каждый вопрос из приложения А**: понятность для родителя, возрастные ориентиры (особенно 1–2, 2–3 и 5–7 лет), верно ли «да = хорошо». Нужны ориентиры именно для узбекского языка (порядок появления звуков в узбекском отличается от русского и английского; в вопросах про звуки «р», «л», «с», «ш» это существенно) и для двуязычных семей.
2. **Пороги** (раздел 4): 0,8 / 0,5 для области, правило быстрого скрининга (≥ 80% и ни одного «нет»), потолок «Наблюдаем» для общего уровня. Это не валидированные значения, они выбраны осторожно. Нужны ваши цифры или обоснование.
3. **Сужение подробной оценки по «что тревожит»** (таблица в разделе 3) и правило «добавить области, где быстрый скрининг не «Хорошо»».
4. **Советы без экрана (приложение Б)**: безопасность, пригодность для возраста, нет ли в них лечения или «массажа»; не слишком ли ребёнок нагружен; допустима ли формулировка «не поправляйте, а повторите правильно» и т. п.
5. **Привязка областей к заданиям в приложении** (приложение Б): подходит ли дыхательная игра «Puflash» для плавности, зеркало Огизча для артикуляции, детские игры для понимания и так далее.
6. **Расписание повторов 7/14/30 дней** и правило «улучшение»: нет ли ошибок в логике «если не осталось областей с вниманием или общий уровень вырос». Нужно ли показывать «Подумайте о консультации» после первой проверки при большом числе областей с вниманием (сейчас: только подсказка с перечнем, куда обратиться).
7. **Что делать при смене возрастной группы между повторами** (сейчас возраст в повторе тот же, что в базовой проверке; новый возраст можно выбрать, и тогда вопросы другие).

### 9.6. Известные ограничения (честно)

- Нет валидации ни для одного вопроса и порога. Нет референсной выборки.
- Один набор вопросов `asd` на возраст 1–5 лет не учитывает, что часть ориентиров (например, указательный жест) в 1 год ещё может отсутствовать.
- Вопросы про сенсорные реакции звучат как «хорошо — спокойно переносит»; для части детей это не показатель развития. Специалист может решить убрать область или объединить её с «Наблюдаем» по умолчанию.

- Возраст запоминается по выбору, а не по дате рождения (даты рождения приложение не хранит).
